# 2026.03.00

> reference: Facts, options, APIs.

This document covers the upgrade process from 2026.02.00 to 2026.03.00. This upgrade includes RabbitMQ configuration and data migration, and Elasticsearch index migration.

> **Important:** We do not support upgrading directly to this version from prior to 2026.02.00.

## Prerequisites
- Access to the Helm chart version `3.0.0`. You may need to run `helm repo update` to grab the latest version.
- [kubectl](https://documentation.cluedin.net/paas-operations/upgrade/guide/required-tools#kubectl)
- [Helm](https://documentation.cluedin.net/paas-operations/upgrade/guide/required-tools#helm)
- [platform-upgrade-v3-stage1.yml](https://documentation.cluedin.net/assets/yaml/platform-upgrade-v3-stage1.yml) values.
- [platform-upgrade-v3-stage2.yml](https://documentation.cluedin.net/assets/yaml/platform-upgrade-v3-stage2.yml) values.
- A single-node Elasticsearch deployment. The supplied migration scripts do not support multi-node clusters; contact CluedIn support for a separate migration procedure.

## Guide

> **Important:** Before any upgrade takes place, ensure you have taken a snapshot or **backup of all your running PVCs** in your AKS cluster and the **Azure SQL databases**. This is very important as databases will be upgraded during this process.

### Stage 2: Stop workloads and back up data

  1. Apply the **stage 1** upgrade values file by running the following:

      ```bash
      # ${CustomValues} refers to the values file you have amended with the above changes. Please type the full path here.

      helm upgrade cluedin-platform -n cluedin cluedin/cluedin-platform \
          --version 3.0.0 \
          --values ${CustomValues} \
          --values platform-upgrade-v3-stage1.yml \
          --wait \
          --timeout 10m0s
      ```

   Apply the stage values file last so that it overrides your custom values.

  1. Check the pods. Wait until all CluedIn application pods have stopped.

  1. Take a backup before continuing. Confirm the backup completed successfully.

   The next stage deletes original Elasticsearch 7.x indices after reindexing and verification. This cannot be reversed through a Helm rollback; a pre-migration data backup is required for recovery.

### Stage 3: Migrate infrastructure data

  1. Apply the **stage 2** upgrade values file by running the following:

      ```bash
      # ${CustomValues} refers to the values file you have amended with the above changes. Please type the full path here.

      helm upgrade cluedin-platform -n cluedin cluedin/cluedin-platform \
          --version 3.0.0 \
          --values ${CustomValues} \
          --values platform-upgrade-v3-stage2.yml \
          --wait \
          --timeout 30m0s
      ```

   Apply the stage values file last so that it overrides your custom values.

  ❗ The time required depends on the amount of data. The timeout shown is an example; allow sufficient time for your environment. A Helm timeout alone does not mean the migration has stopped or completed.

  1. Monitor the migration logs in elasticsearch:

      ```bash
      kubectl get pods -n cluedin
      kubectl logs cluedin-elasticsearch-0 -n cluedin -c cluedin-upgrade-es8
      kubectl logs cluedin-elasticsearch-0 -n cluedin -c cluedin-upgrade-es9
      ```

  1. Wait until the deployment finishes.

  1. Perform the validation:
      - Confirm Elasticsearch is Ready and both init containers completed successfully.
      - Confirm RabbitMQ is healthy and its existing data was retained.
      - Review migration logs for failures. Application pods remain stopped during this stage.

   If there are any issues during the upgrade process, please do not hesitate to reach out to CluedIn support.

### Stage 4: Run the application upgrade

  1. Apply your custom values without either upgrade stage files:

      ```bash
      # ${CustomValues} refers to the values file you have amended with the above changes. Please type the full path here.

      helm upgrade cluedin-platform -n cluedin cluedin/cluedin-platform \
          --version 3.0.0 \
          --values ${CustomValues} \
          --set application.system.upgradeMode=true \
          --set application.system.runDatabaseJobsOnUpgrade=true \
          --set application.system.runNugetFullRestore=true \
          --wait \
          --timeout 10m0s
      ```
      After a few minutes, it should complete successfully.

1. Wait until the deployment finishes.

1. Perform the validation:

    - Make sure that all pods are healthy and all jobs are completed.

    - Ensure that there are no errors in the pod logs.

If there are any issues during the upgrade process, please do not hesitate to reach out to CluedIn support.

### Stage 5: Run Data Upgrade

  1. Apply data upgrade by running following command:
      ```bash
      # ${CustomValues} refers to the values file you have amended with the above changes. Please type the full path here.

      helm upgrade cluedin-platform -n cluedin cluedin/cluedin-platform \
         --version 3.0.0 \
         --values "${CustomValues}" \
         --set application.system.upgradeMode=true \
         --set application.bootstrap.dataUpgrade.toVersion=Version500 \
         --wait \
         --timeout 30m0s
      ```

  1. Monitor the server pod logs for the data upgrade progress.

  1. Validation:

      - ❗ Confirm the data upgrade completed successfully and its resource reached `Active` state.

### Stage 6: Finalize Upgrade

1. Run the final stage of the upgrade to bring the system back online (disable upgrade mode):

    ```bash
    # ${CustomValues} refers to the values file you have amended with the above changes. Please type the full path here.

    helm upgrade cluedin-platform -n cluedin cluedin/cluedin-platform \
      --version 3.0.0 \
      --values ${CustomValues} \
      --set application.system.upgradeMode=false \
      --set application.system.runDatabaseJobsOnUpgrade=false \
      --set application.system.runNugetFullRestore=false \
      --wait \
      --timeout 30m0s
    ```

1. Validation:
    - Ensure no errors in the pod logs.
    - Verify the server starts in normal mode.
    - Ensure cluedin-ui pod is Running.

If there are any issues during the upgrade process, please do not hesitate to reach out to CluedIn support.
